- **Moved, by the signal grep** (verified per file; no name collision):

  The `filterwarnings` entry follows `tests.unit.test_name_coercion`.
- `tests/contract/test_test_layout.py`: no root `tests/test_*.py`; every collected item has exactly

- `pytest -m <kind> --co`: unit 1435, integration 528, contract 2020, packaging 57 = **4040**, every

**Three breakages the move exposed, each fixed as a pure rewire:**
1. **`collect_ignore_glob`** named the `pynng` / `systemd` modules by root path, so the move made
   them collect, and error, on a box without the dependency (`ModuleNotFoundError: systemd`). The
   globs follow the moves, and the layout test now fails on a stale glob.
2. **Six moved modules** found `tests/data` / `tests/tmp` relative to `__file__`. Fourteen sites
   were moved up one level.
3. **`test_configmanager`'s fixture** set `CUEMS_CONF_PATH` with `environ[...] = ...` and never
   restored it. At the root it was collected after `integration/`, so the leak was invisible. Inside
   `integration/` it runs before `test_default_mappings_fresh` and `test_remint_documents_valid`,
   which then read its fixture identity. It now uses `monkeypatch.setenv`. The leak pre-dated 017;
   the move only made it visible.

**Pass set** (JUnit outcome per test, module path normalised `tests.<kind>.` → `tests.`): identical
before and after, except the three new `test_test_layout` tests (PASSED). The 7 pre-existing
failures are unchanged.

**Run as the current user, not with `unshare -r`.** `-r` maps to root inside the namespace, and root
ignores mode `0o444`, so `test_helpers::TestCheckPath::test_tmp_file` fails there. That failure
comes from the harness, not the code; `unshare -cn` maps uid 1000.

**A fourth pre-existing order leak was exposed and fixed (test-only).** `tests/unit/test_version_steps.py::test_a_multi_step_walk_runs_every_step_in_order`
(since 008, `ff65dcc`) registered three scratch conversions into the module-global
`versioning._CONVERSIONS` and never removed them. The full suite runs `contract/` before `unit/`,
so `test_additive_surface_invariants::test_the_conversion_registry_is_unchanged` never saw them. The
offline check runs `unit` first, and that test failed. It reproduces on arm A `5e4c637` with the same
two-file invocation (1 failed, 13 passed). The test now registers into a `monkeypatch`ed copy of
the registry: 14 passed in either order. No source change.
