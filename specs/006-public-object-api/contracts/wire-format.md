# Contract: the wire format

**Feature**: 006-public-object-api · **Date**: 2026-08-18
**Evidence**: `specs/planning/xml-rebuild-05-ui-wire-contract.md`

`cuems-editor` transmits this dict **verbatim** to the Angular UI on `project_load`. It is the
heaviest, most-used path in the system, and it crosses a repository this feature does not
edit. If it moves, the UI breaks in production and nothing in this repository's tests would
have caught it — which is why the byte-equality assertion is the feature's gating test rather
than one test among many.

---

## W1 — Byte-identity (the hard constraint)

For **every** corpus script document:

```
CuemsScript.load(path).to_wire()  ==  <pre-feature XmlReaderWriter.read() golden>
                                       minus the schemaLocation key
```

- Goldens live in `tests/golden/dict/*.reader.json`, captured before this feature.
- **They are never regenerated to make a test pass** (standing rule 3). A diff is a bug in
  the projection, not a stale golden.

### W1a — "byte-identical", defined (CHK022, CHK023, CHK024, CHK029)

A dict has no bytes, so "byte-identical" is a metaphor borrowed from the XML goldens where it
is literal. Retired here in favour of one stated predicate. Two dicts are **equal** when:

1. **Recursive structure** matches — same keys at every depth, same list lengths and order.
2. **Scalar type** matches exactly: `"True"` is not `True`, `"0"` is not `0`, `1` is not `1.0`.
   Type equality is checked with `type(a) is type(b)`, not `==`, because `True == 1` in Python
   and that is precisely the confusion F21 was made of.
3. **Key order** matches **the golden's order**. Stating it against the golden rather than
   against "declared order" or "arrival order" sidesteps an ambiguity that would otherwise be
   unresolvable: decode preserves *arrival* order while `items()` is *declared* order, so
   "unchanged" needs a referent and the golden is the only stable one.
4. **Text** compares as Python `str` at equal codepoints — an escaped and an unescaped form of
   the same character are equal (C6).

**Scope of the claim, so "100%" is checkable**: every corpus document bound to the `script`
schema — the set `tests/support/corpus.py::script_documents()` returns, whose count is recorded
in `specs/006-public-object-api/baseline.md`. The same predicate governs W8's config comparison
against `*.config.json`.

### W1b — Documents added by this feature, and why they are added *first*

Two corpus documents are new: the Latin-locale fixture (FR-036d) and the fade-cue document
(FR-024b). Both are **added in Phase 1, before any projection code exists**, and their goldens
are captured by the existing pre-feature harness in that same phase.

This is a sequencing requirement, not a convenience. A golden captured *after* the projection
changed is generated by the very code it is supposed to arbitrate, so the byte-identity
assertion for that document cannot fail — the document would join the corpus already exempt
from the guarantee every other document carries, and nothing in the suite would say so. Adding
both up front costs nothing (neither document's content depends on the feature) and keeps
"100% of corpus script documents" a single population rather than a proven set plus two
passengers.

The same rule fixes the write side: a script document added in Phase 1 gets an XML golden
carrying the `@@SCHEMAS_DIR@@` placeholder, so it must be included in the deliberate
schema-location golden edit (W6). That edit is stated against **every file under
`tests/golden/xml/`**, never a fixed count, precisely so adding a corpus document cannot
silently leave one behind.

**Payload parity (SC-003)** uses this predicate over the **full** dict, not a chosen field
subset, so "0 differing fields" means the two projections are equal under W1a and nothing is
excluded by selection.

## W2 — Scalars

| XSD type | Wire form | Note |
|---|---|---|
| `BoolType` | `"True"` / `"False"` — **strings** | `cms:BoolType` is `xs:string` restricted to those two literals. The UI reads `cueData.enabled === true \|\| cueData.enabled === 'True'` and **writes back the string form**. Converting to JSON booleans is deferred item X1 and a file-format migration — explicitly forbidden here |
| `PercentType`, `LoopType`, channel types | `int` | |
| `UnitFloat`, `PositiveUnitFloat` | `float` | |
| `UuidType`, `TargetType` | uuid string; unparseable values pass through as their raw string | what keeps the editor's nil `Media.id` loading |
| `CTimecodeType` | `{"CTimecode": "…"}` | |
| Enum types | member name | |
| Wildcard (`ui_properties`, `xs:anyType`) | scalars as **strings** | X10's documented fallback |
| everything else | `str` | |

## W3 — Structure

- **Repeated elements keep `CMLCuemsConverter`'s current decode shape, exactly.** F22: that
  shape is a frontend contract, not an internal convention. D5's thin subclass exists to
  preserve it.
- Cue wrapping (`{"AudioCue": {…}}`) is unchanged.
- Key order is unchanged.

## W4 — What is removed, and what is added

| Change | Direction | Note |
|---|---|---|
| `{http://www.w3.org/2001/XMLSchema-instance}schemaLocation` key | **removed** from the wire dict | F23. An XML artifact with no meaning to the UI. Evidence that no consumer reads it is a deliverable |
| Runtime attributes | **cannot appear**, by construction | the projection walks declared fields; `RUNTIME_FIELDS` are not among them |
| `initial_template` payload | **changes** to match | booleans become `"True"`/`"False"`, `ui_properties` integers become strings |

**W4 changes ship in one release** (FR-031), so the wire format moves once rather than twice
from a consumer's point of view. The unit is the **release, not the commit**, and the two
halves are not symmetrical:

- The **key's absence** is a property of `encode_wire` from the moment it is written. W1's
  gate compares against the golden *minus* that key, so the projection is never correct while
  emitting it. There is no "drop the key" step — requiring one would mean writing the
  projection wrong on purpose so that something remained to change.
- The **relative schema location** (W6) changes existing output and is therefore a real edit
  at a point in time, with a deliberate golden update behind it.

What FR-031 forbids is a *release* in which one has moved and the other has not. Both are
unreachable by any consumer until the public surface ships, and they ship together.

## W5 — The two payloads become one projection

Today the UI receives two mutually inconsistent encodings of the same document type (F21):

| | `initial_template` (via `__json__`) | `project_load` (via the converter) |
|---|---|---|
| `enabled`, `autoload`, `timecode` | `bool` — `true` | `str` — `"True"` |
| `ui_properties.warning` | `int` | `str` |
| `schemaLocation` | absent | **present** |

After this feature both come from `to_wire()`. `project_load` is **byte-identical** except for
the dropped key; `initial_template` moves to match it.

**No frontend change is required** — the dual-check already absorbs the boolean case. The
frontend team is told anyway, because they own the follow-up that removes the dual-check once
both payloads agree.

## W6 — The written document

`xsi:schemaLocation` changes from the writing machine's absolute path to the **bare schema
filename**.

- Today every show file carries the writing machine's local layout, so documents are neither
  portable nor reproducible (F24), and goldens are machine-dependent.
- Nothing resolves the value: validation uses the explicitly loaded schema object.
- `tests/contract/test_legacy_compatibility.py` already proves the read side across all three
  forms — absolute, relative, absent — as 004's FR-035c/SC-019. **Files already on disk are
  unaffected.**
- The golden update this requires is stated against **every file under `tests/golden/xml/`**
  (three today, more once W1b's documents land), never a fixed count — so adding a corpus
  document cannot leave one golden behind in the old format.

## W8 — Config documents project through the same engine

Config objects expose `to_wire()`/`to_json()` from the **same** `encode_wire` that produces the
show payload (FR-014a). One implementation, two domains.

- **Not transmitted to the UI today.** This exists because opening configuration files to the
  UI is planned follow-on work. Building the projection once, here, is what stops a second
  parallel definition being written then — the drift mechanism behind F15's three incompatible
  mappings shapes.
- **Near-free to build**: `encode_wire(obj, spec)` is already schema-generic, and the config
  types become registry-bound model classes in this feature regardless.
- **Byte-identity target already exists**: `tests/golden/dict/*.config.json`, captured before
  this feature by the same harness that captured `*.reader.json`. No new goldens are needed and
  none are regenerated.
- **W2's scalar table applies unchanged.** Config carries no `BoolType` UI contract, but the
  same adapters produce the same forms, which is the point of sharing the engine.
- **The show-side byte-identity guarantee (W1) is unaffected.** Config projection is additive;
  it changes no code on the script path.
